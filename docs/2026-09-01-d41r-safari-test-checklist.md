## 一、四点检查清单（逐项步骤 + 预期 + 判定标准）

### 检查点 1 · 100dvh 回退（I-5）

- **背景**：`src/index.css:179` 的 `@utility viewport-full` 写法为 `height: 100vh` + `@supports (height: 100dvh) { height: 100dvh }`，专门覆盖 Safari 15.0–15.3 不支持 `dvh` 的情况。风险表现为：聊天页高度塌陷（内容被压扁）或底部输入框被裁切。
- **环境**：Safari 桌面窗口（≥1440px 宽）+ 移动仿真 375×812 各测一遍；重点看**聊天页**（`/chat`）。
- **步骤**：
  1. 进入聊天页，观察整页高度：页面是否恰好铺满视口（无上方留白、无下方被地址栏遮挡的裁切感）。
  2. 滚动到底部，确认最后一条消息和输入框完整可见。
  3. 键盘可选中页面内任意元素后上下拖动窗口高度（模拟 Safari 工具栏收起/展开），观察布局是否跟随、无跳变闪烁。
  4. 移动仿真档重复 1–3。
- **预期结果**：页面铺满视口，无高度塌陷、无底部裁切、窗口高度变化时平滑跟随。
- **判定标准**：
  - ✅ 通过：上述 4 步全部正常。
  - ❌ 失败：出现整页可拖动出白底（`100vh` 超出）、底部输入框被裁切 ≥1/3、或窗口高度变化时布局塌陷/闪烁。

### 检查点 2 · backdrop-filter 毛玻璃（I-3 范围）

- **背景**：Landing/Swap/VR/Match 四页使用了 `backdrop-filter`（Tailwind `backdrop-blur-*`）。Safari 需要 `-webkit-backdrop-filter` 前缀（Tailwind 已自动加），风险表现为元素变白块或滚动掉帧。
- **环境**：Safari 桌面档；重点页：SwapPage（换乘页导航/卡片）、MatchPage（匹配卡片）、LandingPage（顶部导航）。
- **步骤**：
  1. 逐页打开，找到毛玻璃元素（半透明磨砂质感的导航条/卡片/弹窗）。
  2. 观察其背后内容是否有模糊透出效果（而非纯白/纯色死块）。
  3. 在该页快速上下滚动 5–6 次，感受是否有明显掉帧、闪烁或元素消失。
  4. 若有弹窗/抽屉类组件，打开关闭 2–3 次看渲染是否正常。
- **预期结果**：毛玻璃正常磨砂透出、滚动流畅、无白块闪烁。
- **判定标准**：
  - ✅ 通过：所有毛玻璃元素渲染正确 + 滚动无可感知卡顿。
  - ❌ 失败：任一元素显示为不透明白块/黑块，或滚动帧率明显低于同页其他动画。
  - 🟡 部分通过：渲染正确但轻微掉帧 → 记录页名与操作，由监督人判定是否可接受（性能类问题不在冻结拦截范围）。

### 检查点 3 · focus-visible 键盘焦点（I-2）

- **背景**：`src/index.css:101` 全局定义 `:focus-visible { outline: 2px solid var(--color-brand-400); outline-offset: 2px }`；各按钮另有 `focus-visible:ring-4 ring-brand-200`。风险：Safari 默认对按钮不显示焦点环（需 ⌥Q 开启）。
- **环境**：Safari 桌面档；页面：落地页 → 设置页（SetupPage 按钮最密集）→ 聊天页。
- **步骤**：
  1. **先开启 Safari 键盘焦点**：菜单 编辑 → 键盘导航与控制（或按 ⌥Q），确保「按下 Tab 键以高亮页面上的每一项」开启（Safari 15+ 需要一次性授权）。
  2. 从落地页开始连按 Tab ≥10 次，观察每次焦点位置是否有清晰可见的描边环（粉色 2px outline 或 ring）。
  3. 重点看**按钮/选项卡**类元素（Safari 最易丢失 focus 样式的类型），确认它们也有描边。
  4. 用 ⇧Tab 反向走几步，确认描边同样出现。
  5. 在设置页（三道情景题选项）重复 2–4。
- **预期结果**：所有可交互元素获得键盘焦点时出现清晰可见的 brand-400 描边，无「焦点消失」（focus 落在某元素但屏幕上无任何视觉变化）。
- **判定标准**：
  - ✅ 通过：Tab 遍历 10+ 次中每次焦点均有可见描边，含全部按钮类。
  - ❌ 失败：任一按钮类元素聚焦时无描边（含全局 outline 与 ring 两种样式都缺失）。
  - 🟡 部分通过：仅个别非关键元素缺失 → 记录元素位置，转 Codex 低优先级修复。

### 检查点 4 · woff2 艺术字体渲染（I-9 范围）

- **背景**：三组字体回退链见 `src/index.css:68-71`——`--font-display: 'Fraunces', 'PingFang SC'…`、`--font-serif: 'Cormorant Garamond', 'Songti SC'…`、`--font-script: 'Petit Formal Script', 'Kaiti SC'…`。风险：Safari 15 对 woff2/unicode-range 兼容良好，但若字体加载策略异常会整体回退到系统字体，破坏 Dreamcore 视觉。
- **环境**：Safari 桌面档；页面：落地页（Hero 标题最典型）+ MatchPage（词条卡片用 script 字体）。
- **步骤**：
  1. 打开落地页，看首屏大标题「先聊过，再决定谁更适合你。」：英文衬线部分应为 Fraunces 的艺术字形（笔画有明显衬线与墨水陷阱细节），非系统默认字体。
  2. 打开开发菜单 → 网络检查器，刷新页面，过滤 `woff2`：确认 woff2 文件实际加载成功（状态 200，无失败项）。
  3. 进入 MatchPage，查看恋爱词条/署名处使用的手写体（Petit Formal Script / 楷体回退），确认显示为手写风格而非黑体。
  4. 若 Safari 出现字体闪烁（FOUT），记录出现时长（<300ms 可接受）。
- **预期结果**：标题为衬线艺术字体、手写体正常渲染、woff2 全部加载成功。
- **判定标准**：
  - ✅ 通过：三组字体链均按预期渲染（或中文合理回退到苹方/宋体/楷体且视觉协调）。
  - ❌ 失败：标题显示为系统黑体/宋体（英文部分未用 Fraunces/Cormorant 字形），或网络面板 woff2 有 404/加载失败。
  - 🟡 部分通过：仅手写体回退到楷体但视觉可接受 → 记录，属设计可接受范围。

### （可选）检查点 5 · iOS 真机抽查

- **环境**：iOS 真机 Safari（或 Safari 开发菜单连接的 iPhone），同一 `npm run preview` 地址需改为 Mac 局域网 IP 访问（`--host 0.0.0.0`），或改测已部署的线上站点。
- **步骤**：① 落地页/聊天页横向检查——左右轻扫确认无水平滚动条与横向溢出；② 聊天页观察 BottomNav 是否正确避开 Home Indicator（底部指示条）；③ 点击聊天输入框，确认键盘弹起后页面未整体放大（viewport meta 正确时 iOS 不缩放）；④ 中文楷体回退检查同检查点 4 第 3 步。
- **预期**：四项均正常。
- **判定**：✅ 全过 / ❌ 任一异常记录截图。**时间不足可整项跳过**（PRD 已授权「抽查」性质）。

## 二、建议执行顺序与时间预算

**顺序：3 → 1 → 4 → 2 →（可选 5）**，理由：

1. **先做 3（focus-visible）**：需要一次性开启 Safari 键盘导航授权，且不依赖页面深度状态，落地页即可开始；失败概率相对高（Safari 对按钮 focus-visible 的历史兼容问题），早发现早转 Codex。
2. **再做 1（100dvh）**：需先走完情景题进入聊天页（为检查点 2/4 也完成前置路径），一次路径遍历服务三个检查点。
3. **然后 4（woff2）**：聊天页路径上顺路看 MatchPage，纯观察类，耗时最短。
4. **最后 2（backdrop-filter）**：包含滚动压力测试，放最后避免影响前面的观察稳定性。

**时间预算**：四点合计约 20–30 分钟（不含环境准备 5 分钟与 iOS 真机抽查 15 分钟）。

## 五、异常上报规范

任一 ❌ 项需向 Codex 提供以下 6 项信息，缺一会影响修复定位：

1. **检查点编号与页面路径**（如「检查点 1 · /chat」）。
2. **Safari 版本 + 系统版本**（如 Safari 18.6 / macOS 15.6；真机另加 iOS 版本与机型）。
3. **窗口尺寸/仿真档位**（桌面 ≥1440 / 375×812 仿真 / 真机）。
4. **现象描述**：一句话说清「预期 vs 实际」（如「预期输入框完整可见，实际底部被裁切约 60px」）。
5. **截图**：`docs/evidence/after/safari/` 下的文件名（画面需含地址栏或明显页面特征，便于比对）。
6. **复现步骤**：编号列出从打开页面到出现异常的最短操作序列（含前置授权操作，如 ⌥Q），并注明**必现/偶现**与复现次数（如「3/3 必现」）。
