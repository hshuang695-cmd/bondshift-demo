# 🧱 BONDSHIFT 技术决策记录

📅创建日期：2026年8月18日。

## ✅ 已确定

⚛️前端继续使用React、TypeScript、Vite和Zustand。  
🌐公开测试继续使用当前Netlify演示环境或同项目正式分支。  
🔓首次体验采用匿名会话，不强制登录。  
🛡️大模型密钥必须保存在服务端环境变量。  
🧠每位男友拥有独立消息、记忆与关系状态。  
📊公开测试必须记录真实漏斗事件。  
🔒分析事件不上传完整聊天内容。

## ✅ 2026年8月20日已确认决策

### 🤖 大模型供应商

✅主模型供应商确定为DeepSeek API。  
✅公开测试总预算上限确定为150元人民币。  
🛡️API密钥只允许配置在本地或Netlify服务端环境变量中。  
💡前端继续保留模板回复作为接口失败时的降级。  
💰应用侧应记录调用次数，并在预算消耗接近50元、100元和135元时人工复核。  
⛔达到150元预算上限后应暂停公开模型调用，避免失控支出。

### 📊 分析服务

✅用户接受使用第三方匿名分析服务。  
💡具体服务在埋点实施日确定，选择标准是能够快速查看漏斗、支持匿名事件和方便导出。  
🔒任何第三方事件都不得包含完整聊天内容或直接身份信息。

### 💾 持久化方式

✅P0阶段确定使用匿名ID加本地持久化。  
🟡跨设备保存、数据库和登录保留为P1功能。  
🎯公开测试不以跨设备关系恢复作为上线条件。

## 🟡 后续实施时仍需完成

🟡在Netlify中创建DeepSeek服务端环境变量（服务端Function与变量读取代码已完成）。
🟡确定第三方分析服务并创建项目。  
🟡为公开测试配置调用次数与异常失败监控。  
🟡不得将真实API密钥写入本文档或Git仓库。

## ⚠️ 实施约束

⚠️前端代码不得包含大模型密钥。  
⚠️换乘时不得清空全部用户数据。  
⚠️旧男友数据不得混入新男友上下文。  
⚠️公开测试不得依赖复杂账户系统才能开始。  
⚠️8月28日后不得更换核心技术方案。

## ✅ 2026年8月26日实施结果

✅`/api/chat`由Netlify Function代理DeepSeek，前端构建不包含API密钥。

✅每次模型请求只携带当前男友最近10条消息，维持关系上下文隔离。

✅浏览器使用不含直接身份信息的稳定匿名ID。

✅接口失败时先保留用户消息，再使用本地人格引擎安全降级，并提供重试。

✅服务端增加25秒超时、长度限制、输入校验和`no-store`响应。
