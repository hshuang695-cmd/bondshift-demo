# ✅ BONDSHIFT 两周改版验收标准

📅适用版本：2026年8月31日公开测试版。

## 🚪 落地页

- ✅首次访问展示产品定位，而不是直接进入默认男友首页。
- ✅用户能够在10秒内理解AI陪伴和关系换乘机制。
- ✅页面提供明确的“开始体验”主按钮。
- ✅页面提供AI生成、隐私和测试版本说明。
- ✅手机和桌面端均不存在横向溢出。

## 🧩 情景测试

- ✅测试包含三道与情感支持有关的情景题。
- ✅用户能够在90秒内完成测试。
- ✅用户可以返回上一步并修改答案。
- ✅测试结果能够稳定映射到推荐男友和陪伴风格。
- ✅用户不填写MBTI也能够完成匹配。

## 💝 匹配与首次相遇

- ✅匹配结果说明“为什么适合”，而不只显示百分比。
- ✅男友第一条消息与用户答案相关。
- ✅页面同时提供快捷回复和自由输入。
- ✅用户无需注册即可进入聊天。
- ✅从落地页到首次对话没有断链或死路。

## 🤖 真实AI聊天

- ✅大模型密钥只存在服务端环境变量。
- ✅用户可以进行超出固定模板的开放对话。
- ✅接口加载状态、失败状态和重试入口清晰可见。
- ✅接口失败时使用友好降级，不丢失用户消息。
- ✅每个匿名用户都有稳定但不包含个人隐私的会话ID。

## 🧠 记忆与关系数据

- ✅男友A和男友B的消息完全隔离。
- ✅男友A和男友B的记忆完全隔离。
- ✅男友A和男友B的关系评分完全隔离。
- ✅换乘后旧男友消息不会显示为新男友消息。
- ✅刷新页面后关系评分不发生随机变化。
- ✅新用户初始换乘次数为零。
- ✅示例数据不会混入真实用户数据。

## 🔄 首次换乘

- ✅用户可以看到两个男友对同一问题的不同回应。
- ✅页面解释差异来自陪伴风格，而不是简单优劣排名。
- ✅用户可以选择留下或试乘下一位。
- ✅确认换乘前明确说明记忆和关系如何处理。
- ✅换乘后自动进入新男友的首次相遇场景。
- ✅用户能够在首次访问的5分钟内完成换乘。

## 📣 分享传播

- ✅画像卡不展示未经用户确认的私密聊天原文。
- ✅画像卡包含情感需求、陪伴偏好和匹配类型。
- ✅用户可以将画像卡保存为图片。
- ✅用户可以复制带来源参数的分享链接。
- ✅分享链接能够正常返回落地页。
- ✅生成和分享动作均有真实埋点。

## ⚡ 性能与兼容性

- ✅首屏图片传输目标低于1.5MB。
- ✅主JavaScript目标低于300KB。
- ✅非首屏图片使用懒加载。
- ✅页面使用适配移动浏览器的动态视口高度。
- ✅键盘弹出后聊天输入框仍可见。
- ✅用户可以缩放页面。
- ✅关键图标按钮拥有可访问名称。

## 🧹 工程质量

- ✅`npm run build`执行成功。
- ✅`npm run lint`执行成功且没有错误。
- ✅核心数据逻辑至少具有可重复运行的验证脚本或测试。
- ✅生产环境不输出包含用户聊天内容的调试日志。
